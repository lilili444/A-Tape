# 开发记录

这个项目从想法到第一版上线的来龙去脉。只记录技术上的决定和原因，不放日记内容。
规则看 `CLAUDE.md`，用法看 `README.md`，这里记录“为什么”。

---

## 起点（2026-11-14）

- 想用 vibe coding 做几个自我管理的小程序，手机和电脑都能通过浏览器打开，只给自己用。
- 最初想做的是**纪念日 / 倒数日**：现有的两款买断小 app 都只满足一部分需求。日记是后来加上的：苹果“手记”没有标签功能，用起来不顺手，于是先做日记练手。
- 担心“GitHub 只能有两个私有仓库”，后来查证是记错了：免费账号的私有仓库不限量。真正的限制是 **GitHub Pages 免费版只能发布公开仓库**，而且就算付费，Pages 网站本身也是谁都能打开的。
- 结论：**代码公开没关系，数据必须另外存在私有的地方，并且要登录才能读取。**

## 选后端

考虑过的方案：

| 方案 | 结果 |
|---|---|
| 数据只存在浏览器里 | 只适合过渡阶段：换设备就看不到，Safari 七天不访问还会自动清掉 |
| 用另一个 GitHub 私有仓库存 JSON，网页用 token 读写 | 可行，但不是为这个设计的，多设备同时修改容易互相覆盖 |
| Firebase | 不会因为不活跃被暂停，但 2026 年 2 月起存照片必须绑卡，而且没有消费上限 |
| **Supabase 免费版** ✅ | 1GB 文件 + 500MB 数据库，不用绑卡，超额只会停用、不会扣费，自带登录 |

- 看到过一篇“Supabase 免费版是陷阱”的帖子。逐条核对后的结论：暂停不会删数据；“免费项目不限量”是错的（最多两个）；付费确实贵，但我们不会主动升级。真正的弱点是**免费版没有自动备份**，所以备份要自己做（见待办）。
- 也重新考虑过 **Obsidian**：免费、数据是本地的 Markdown 文件、有插件。但 Lili 以前实际用过，最后又回到了苹果手记；而且纪念日、倒数日这类个性化规则在 Obsidian 里很难做好。所以决定**继续自己做**。
- 为了降低以后迁移的成本：数据只用一张通用表加 JSON；和 Supabase 打交道的代码只集中在 `Store` 这一块；“导出备份”的文件是完整的、和平台无关的数据。

## 版本

### v0.1 本地版（2026-11-22）
- 参考苹果“手记”：时间线、写日记、照片、收藏、搜索、统计。外加**标签**（可以多个、自动提示、改名、删除）。
- 视觉方向由 Lili 定为“**极简纸面风**”：暖白纸底、很淡的纸纹颗粒、蓝黑墨水色、衬线字体，日记之间用细线隔开而不是卡片框，编辑时像盖上一张纸。
- 数据存在浏览器的 IndexedDB 里，带导出 / 导入，为接云端做准备。

### v0.2 日记本与视图
- 去掉侧栏顶部的标题和副标题。
- 去掉“收藏”和“有照片”两个分类，换成**日记本**（可以自己新建、改名、删除）。收藏按钮暂时保留，要不要留待定。
- 新增三种查看方式：时间线 / **三年日记 / 五年日记**（把往年同一天叠在一页）。

### v0.3 上云
- 接入 Supabase，加上登录页；账号在后台手动建好，然后**关闭注册**。
- 为了方便 Lili 自己改视觉，把单文件拆成 `index.html` / `style.css` / `app.js`。
- 新增 `README.md`。

### v0.4 两个板块 + 手机版（2026-11-22）
- 项目分成两个板块：**手记**（日记）和**纪念日 / 倒数日**（筹备中）。两边的数据放在同一个 Supabase 项目里，界面分开设计。这样只需要登录一次、备份一套，两边还能互相关联（比如三年日记里提示纪念日）。
- “浏览”改名“视图”；侧栏顶部加了极简小日历（有日记的日子显示小圆点）。
- 统计做成单独的一页，参考苹果手记的 Insights：连续天数、每周连续、每月篇数柱状图、字数、照片、录音。
- 附件：**录音**（≤50MB）和**链接卡片**（歌、电影、文章等）。**不做视频**：太占空间，免费版单个文件上限也只有 50MB。
- 照片统一压缩到长边 1600px（Lili 认为这个清晰度够用）。
- 手机版：Lili 的要求是不要让一大块导航占满屏幕、一打开就能看到日记。于是做成顶部一排 6 个小按钮（视图 / 日记本 / 标签 / 搜索 / 统计 / 备份），点开才展开面板；右下角放一个“写”按钮。只在窄屏（≤760px）生效，电脑上仍然是左侧栏。

## 从苹果手记导入（2026-11-22）

- 苹果手记导出的是一个 ZIP，里面每篇日记一个 HTML 文件，附件放在 `Resources/` 里。
- **导出文件里没有 Journal 信息**：试过按单个 Journal 导出、打印成 PDF，都不行。Lili 原本是用多个 Journal 来代替标签的，所以标签只能导入后手动加。
- 日记本按日期划分：本科（2024-01-14 – 2025-04-10）、英国（2026-09-17 – 2026-11-22）、其余日期归 Gap。两头的日期都算在内。
- 导出文件里**只有日期，没有时间**，所以同一天的几篇按原来的先后顺序排，时间从 12:00 开始每篇加一分钟。
- 照片其实都是 HEIC 格式，连扩展名写成 `.jpeg` 的也是；而且已经被苹果缩小过，不是原图。转换环境里的 ImageMagick 读不了 HEVC 编码，所以写了一个小解析器：从 HEIF 容器里取出 HEVC 图块，用 ffmpeg 解码，再拼回整张图。之后统一压到 1600px。
- 录音作为附件导入。视频、音乐、心情记录、运动记录写成日记末尾的“【手记附件】”文字说明。
- 核对结果：319 篇正文和原文件逐字一致，日记本没有分错。2026 年的篇数、照片数、录音数（149 / 10 / 1）和苹果手记的统计一致。
- 统计里的连续天数和苹果手记对不上（比如最长连续天数这边是 48 天，苹果是 5 天）。推测苹果是按“实际写下的那天”来算，这边是按日记上的日期来算，没有验证。

## 踩过的坑

- **`permission denied for table records`**：只写了 RLS 规则，还不够。较新的 Supabase 项目在 SQL Editor 里建表后，不会自动把表授权给 `authenticated`，需要手动 `grant`。已经写进 `schema.sql`。
- **浏览器缓存导致页面全乱**：更新后，浏览器拿到了新的 `index.html`，却还在用缓存里旧的 `style.css` 和 `app.js`（GitHub Pages 会让浏览器缓存 10 分钟）。结果电脑上冒出手机版的按钮，点什么都没反应。解决办法：给文件加 `?v=` 版本号，每次更新都要加 1。
- **空仓库没有 “Add file” 按钮**：第一次上传要走空仓库页面上 “uploading an existing file” 那个链接。
